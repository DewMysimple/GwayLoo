# module-replication 支线工作区入口

本目录不是主线应用的源码子目录，而是用于隔离开发、验证和记录支线项目的工作区域。

## 路由规则

- 每个直接子目录都是独立项目，拥有自己的开发环境、依赖、资产和 `wiki_memory/`；是否由某个 Git 分支跟踪，不改变项目的运行环境与记忆边界。
- 未明确指定某个子项目时，不要进入、读取、搜索、运行或修改任何子项目。
- 用户明确指定 `module-replication/<项目>/` 后，只进入该项目，并先读取该项目根目录的 `AGENTS.md`。
- 随后按该项目 `AGENTS.md` 指定的顺序读取本地 `wiki_memory/`；不要默认读取 Verminoble 主线的 `wiki_memory/`。

## 记忆与日志边界

- 支线任务的当前状态、决策、知识和工作日志只写入目标子项目的 `wiki_memory/`。
- 不把支线开发日志写入 `C:/Users/Administrator/Desktop/Verminoble/wiki_memory/`。
- 主线记忆只记录工作区边界策略本身，以及主线入口规则的维护；这不构成支线开发日志。

## Git 边界

- 本目录不自动创建 Git 子模块或嵌套仓库关系；提交和推送范围由当前明确的仓库、分支和任务决定。
- 入口文档只说明本开发区域的路由、记忆和环境边界，不代表任何具体项目必须使用独立远程仓库。
- 未明确纳入当前分支的项目内容仍应保持忽略；明确纳入时，也必须保持项目自己的环境、资产和 `wiki_memory/` 边界。

## 环境与资产边界

- 子项目可以拥有与主线同名或相同内容的资产，但不得依赖主线的路径、依赖安装、配置、源码或运行时资产。
- 需要复用内容时，在目标子项目内建立自己的副本或配置，并由该项目自己的日志记录来源和变更。
