# Poem 恢复 hK 四瓦片纹理契约

## 目标

修正上一轮对原始 Poem 文字资源的判断，恢复原始 `AK` TextCanvas 的固定 `hK` 数据、四瓦片 UV/像素布局和 `poem/texture` 资源，同时不破坏 Branch 主滚动页面的 DOM 三瓦片实现。

## 原始证据

- `sources/original-extraction/study/app.beautified.js` 约 148824 行定义 `hK`：`width=400`、`height=2304`、`fontSize=30px`、`lineHeight=48`、7 组 paragraphs，包含 `wholeheartedly` 和完整 Despair 长段落。
- 同一 `AK` 类的 `_computeDimensions()` 以 `width + 20` 生成 4 个 tile，`fullWidth=4*(width+20)`，并按 `fullWidth/height` 压到正方形纹理的 UV；`texture` getter 返回资源 `poem/texture`。
- 原始 `Q5` TextMesh 使用 `pixelBoxes[0]` 求 `uTileRatio`，采样 `uvBoxes[0..2]`，并以 `.xp-fulltext` 的 rect 计算 UI 相机位置。

## 修改

- `app/src/experience/world/TextCanvas.ts`
  - 增加 `SOURCE_POEM_TEXT_DATA` 和完整 Despair 文本。
  - 暴露 `poemTexture`、`poemCanvasPixelHeight`、`poemTileRatio`、`poemUvBoxes`、`poemPixelBoxes`。
  - 保留主滚动页的 DOM 三瓦片 Canvas、命中检测和动态响应式尺寸，不把 Poem 固定布局写回主滚动窗口。
- `app/src/experience/world/PoemView.ts`
  - Poem TextMesh 改为优先使用 `poem/texture` 与固定 hK UV/比例；资源缺失时保留动态纹理回退，但正常启动路径按源码资源契约运行。
- `app/src/config/assets.ts`
  - 恢复 `/xp/poem/text.png` 为静态启动资源，和原始 Watercolor resource registry 一致。
- `app/scripts/qa-experience.mjs`
  - Poem opening 额外检查 `poemTexture` 绑定、2304 高度、4 个源像素瓦片和三组 shader UV。

## 验证

- `node --check scripts/qa-experience.mjs`：通过。
- `npm run verify`：通过；53 个模块构建成功，`assetCount=73`、`failures=[]`。
- `git diff --check`：通过；仅有 Git 的 LF/CRLF 提示。
- `npm run qa`：当前环境 `127.0.0.1:9333` 拒绝连接。
- `npm run smoke`：当前环境找不到 CDP 页面目标；未取得真实纹理像素、shader 编译、横竖屏布局或转场截图证据。
