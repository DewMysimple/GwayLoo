# 主线与 Branch 复刻架构差距比较

## 目标

以 Verminoble 根目录主项目源码为架构事实，对照 `module-replication/Dew-StanzaVerse` 的复刻推演实现，确认两套工程在运行时、渲染、内容、资源、交互和验证方面的实际差距。

## 核心结论

- 主项目是 React 19 + Vite + TypeScript 的双轨迁移工程：默认仍由 `LegacyRuntimeBridge` 加载旧 WebGL，`?runtime=r3f` 才进入 R3F 预览。
- Branch 是独立的 Vite + TypeScript + Three r149 + GSAP 单运行时工程，没有 React，也没有 legacy bridge；`app/src/main.ts` 直接创建 WebGLRenderer，并由 `ExperienceManager`、`WebGLApp` 和 EventBus 组织生命周期。
- Branch 的可维护图形模块比主项目 R3F 预览更完整，包含 26 层纸片、实例化平面、水彩流体、Ground、草、阴影、SDF、LUT、Full Paint 和指针绘画；主项目 R3F 当前主要是 GLB 相机、图集/Mask、基础材质、透明度 reveal 和全屏视频景观。
- 主项目页面内容比 Branch 更完整：主项目通过 `src/content/` 和 `OriginalExperienceTail` 保留诗句、Benefits、Offers、五项 FAQ、分享/奖项静态收尾；Branch 将尾部替换为空白插槽，仅保留 Restart。
- Branch 的文本和页面 DOM 主要静态写在 `app/index.html`，主项目则把 React 挂载壳、内容配置和 legacy DOM 契约分开；主项目更利于渐进切换，但仍存在资源配置未完全接管旧运行时的问题。

## 具体差距

### 运行时与状态

- 主项目使用 React 组件生命周期、`useReducer` 和 `ExperienceRuntimeState`，目前状态粒度覆盖 boot、loading、exploring、landscape、tail、error、滚动进度、诗句编号和场景编号。
- Branch 使用全局单例和命令式状态：`ExperienceManager` 管理转场、雾状态、诗歌、全幅绘画和权益区；`ScrollController`、`AudioManager`、`Resources` 和 EventBus 共同驱动运行时。
- 主项目 R3F 状态契约没有 paint、raycast、brush、full-paint、fog 或 view-transition 状态；这些能力仍在默认 legacy 旧脚本中，或在 Branch 的独立模块中。

### 渲染与 Shader

- 主项目 `LandscapeWorld.tsx` 使用 `MeshBasicMaterial`、图集和 Mask，并在逐帧更新中以简单透明度控制纸片显现；Ground 被隐藏，当前 R3F 没有接入 Branch 的水彩纸面、Ground、草叶和阴影管线。
- 主项目 `SourceAssetPipeline.tsx` 会加载 SDF、噪声、纸张、KTX2、LUT 和 MSDF，但源码明确说明当前渲染器尚未应用全部 Shader 输入；因此“加载了资源”不等于“已经实现了效果”。
- Branch 的 `WatercolorView.ts`、`FluidSimulation.ts`、`ShadowProjection.ts`、`GrassLayer.ts` 与 `shaders/` 将这些效果实际组织进渲染循环，包含实例化纸面、动态模拟区域、地面、草、投影阴影和多阶段水彩 reveal。

### 内容与 DOM

- 主项目的诗句进入 `experienceCopy`，通过 `ExperienceDefinition` 传给 legacy 与 R3F；尾部由 React 按 `tailCopy` 渲染，并保留静态不可导航的 Offers 与 FAQ 内容。
- Branch 的诗句、按钮、音频节点、两个诗句 DOM 副本和尾部插槽都写在 `app/index.html`，图形模块通过 `getElementById` 和 CSS class 绑定它们。
- Branch 当前标题仍是本地 David Whyte 体验研究页，主项目应用展示品牌已切换为 GwayLoo；两边内容目标不是同一版本。

### 资源与路径

- 主项目正式网页资源路径是 `/wp-content/themes/davidwhyte/resources/assets/...`，以兼容 legacy 旧脚本为优先；Branch 的正式运行路径是 `/assets/...`，资源放在 `app/public/assets/`。
- 主项目 `check:assets` 只验证声明资源可读；Branch 额外使用 `source-assets.manifest.json` 做字节和 SHA-256 完整性验证。
- Branch 当前 73 项完整性检查有 4 项失败：`basis_transcoder.js`、`dry.3DL`、`ink.3DL` 和 MSDF JSON 的字节或哈希不一致。它们存在于源镜像中，但当前副本不是 manifest 记录的精确副本。

### 工程与验证

- 主项目依赖 React/R3F/Three，脚本包含 lint、typecheck、Vitest、Playwright、资源检查和构建；主项目 typecheck、build、Vitest 11 项测试和 55 项资源可读性检查通过。
- Branch 依赖 Three r149/GSAP，脚本包含 smoke、CDP QA、构建和完整性验证；Branch typecheck/build 通过，但完整性验证因上述 4 项资源失败。
- 主项目 `npm run lint` 当前会递归扫入已集成的 Branch 源码、Branch `app/dist` 和原始提取目录，产生大量边界外错误；只针对主项目 `src scripts tests` 执行 ESLint 可以通过。这是根目录工具隔离问题，不是主项目业务 TypeScript 本身的类型错误。

## 判定

- 若比较“页面内容和兼容性”，主项目更接近当前交付目标。
- 若比较“可读化 WebGL 重建深度”，Branch 明显领先于主项目 R3F 预览。
- Branch 不能直接被视为主项目真实架构，也不能直接覆盖主项目；它更适合作为水彩渲染与交互模块的推演来源。
- 主项目尚未完成的主要迁移项是：真实纸面 Shader、流体绘画、Ground/草/阴影、Full Paint、诗句全屏转场、指针射线交互、细粒度状态机以及新运行时的完整尾部/交互验收。
