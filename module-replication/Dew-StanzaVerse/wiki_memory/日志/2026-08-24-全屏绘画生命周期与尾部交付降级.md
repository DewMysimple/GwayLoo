# 全屏绘画生命周期与尾部交付降级

## 目标

继续推进 Branch 的两条长期线：深入还原水彩 WebGL 底层，以及提高页面在资源失败、键盘、reduced-motion 和没有 WebGL 时的可交付性。本轮不修改 Verminoble 主线，只修改 `Dew-StanzaVerse/app` 与其自身记忆。

## 代码演进

### Full Paint 生命周期

上一轮已把原站的第 27 个独立 Full Paint simulation region 接入；本轮继续处理它的生命周期：

- `FluidSimulation.resetFullPaint(sceneIndex?)` 只对第 27 个 tile 的 velocity、pressure、divergence、accumulation FBO 区域执行 scissor clear。
- reset 同步清理该实例的中心、半径、force、active、wasActive 和最近场景 UV，不触碰 26 个纸片的局部笔触。
- `FullPaintManager.show()` 每次进入时先 reset；离开后再次进入不继承上次全屏 pigment。
- `qa-experience.mjs` 新增写入后读取 pigment、reset 后读取 pigment 的生命周期断言，并要求第 27 个 region 的 index 为 26。

### 页面尾部与 fallback

- `app/index.html` 恢复本地静态尾部：Companion 说明、3 项 benefits、2 个静态 offer、5 条 FAQ、分享/奖项文案和 Restart。
- offer 和支持信息仅作为本地静态文案，不创建购买、账户、邮件或远程分享链接。
- `Advantages` 恢复 IntersectionObserver 显现和 FAQ 手风琴；FAQ trigger 有键盘 Enter/Space、`role=button`、`tabindex`、`aria-expanded`，无 IntersectionObserver 时直接显示。
- FAQ 在 `prefers-reduced-motion: reduce` 时直接切换高度，不创建 GSAP 展开动画。
- `Resources` 记录失败资源；`main.boot()` 在静态资源失败或初始化异常时进入已有文字 fallback，避免继续用缺失纹理构建场景。
- fallback 下 Restart 在体验未启动时只回到页面顶部，不调用空的 WebGL/UI 实例。

## 验证结果

在 `app/` 执行：

- `npx tsc --noEmit`：通过。
- `npm run verify`：通过；生产构建通过，73 个资源完整性检查全部通过。
- `node --check scripts/qa-experience.mjs`：通过。
- 静态 HTML 检查：FAQ question 数量 5，FAQ trigger 数量 5。
- `python wiki_memory/工具/memory_lint.py check`：通过，33 个 Markdown 页面。
- 本地 Vite `http://127.0.0.1:3000/`：返回 200，HTML 与 `/src/main.ts` 可读取。

## 证据边界与下一步

本轮尝试连接 `127.0.0.1:9333`，仍被拒绝；系统中的 Edge 普通进程没有可用 CDP 端口，启动隔离 CDP 实例也被当前执行环境策略拒绝。因此 `npm run qa` 尚未实际运行，以上不能替代桌面/移动截图和运行时像素证据。

下一轮优先在可用 CDP 浏览器下执行五视口 QA，确认：Full Paint reset 后第 27 个 tile 的 pigment 为零且纸片 tile 保持；FAQ 展开/收起和键盘路径；资源 404、WebGL fallback、reduced-motion 下的可读尾部；以及静态尾部新增后滚动时间线和 Restart 的回归。
