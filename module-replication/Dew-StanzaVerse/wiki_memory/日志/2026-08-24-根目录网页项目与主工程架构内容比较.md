# 根目录网页项目与主工程架构内容比较

## 目标

基于主项目根目录源码，对照 Branch 支线 `Dew-StanzaVerse` 的复刻推演实现，区分两套工程的架构职责、内容范围和实现成熟度。

## 检查范围

- 主项目：根目录 `index.html`、`src/`、`public/`、`package.json`、`tests/`、`scripts/`、`scene_workbench/`
- Branch 支线：`app/index.html`、`app/src/`、`app/public/`、`app/package.json`、`app/scripts/`、`sources/`、`evidence/`
- 两套项目各自的 `wiki_memory/` 与隔离边界

## 已确认结论

- 主项目是从原有网页源码直接改造架构的 Vite + React + TypeScript 工程，保留 legacy 兼容运行时，并通过 R3F 双轨迁移逐步替换实现。
- Branch 支线是独立的 Vite + TypeScript + Three.js/GSAP 复刻推演工程，按源码行为重新组织为可读模块和 Shader；它不是主项目当前真实架构的直接镜像。
- 主项目的页面尾部仍保留原版 Benefits、Offers、FAQ 和收尾内容；Branch 支线已将这些内容清空或替换为空白插槽，只保留布局高度和 Restart。
- Branch 支线对纸片、水彩流体、地面草、阴影和滚动相机进行了更深入的可读化重建，但因此存在与主项目行为契约、资源路径和默认运行时不一致的主动偏离。
- 两套项目拥有独立源码、资产、依赖、生成物、证据和工程记忆；不应互相引用或混写日志。

## 验证摘要

- 本次比较为只读分析；未修改两套业务源码。
- 本日志属于 Branch 支线，主线记忆目录不应保留同名记录。
