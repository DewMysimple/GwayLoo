# 流体 stencil 批处理与四帧活跃历史重建

## 背景

本轮继续只修改 Branch `Dew-StanzaVerse`，不修改根目录主工程。对照 `sources/original-extraction/` 的 Fluid batch pass 后，发现 Branch 虽然已经具备 external force、advection、divergence、pressure、gradient 和 accumulation 的 pass 链，但此前仍把所有 atlas tile 每帧完整绘制到 ping-pong 目标，`WebGLRenderTarget` 也没有 stencil buffer。源码的活跃状态还保留 `wasActive` 到 `wasActive4`，通过 stencil 区域裁剪在指针离开后短暂冲刷旧 tile，再停止无效区域的 GPU 工作。

## 本轮变更

- `FluidSimulation` 的七个 HalfFloat simulation target 开启 `stencilBuffer`，新增独立 `stencilMesh` 与 `simStencilVertexShader`/`simStencilFragmentShader`；主 pass 使用 `EqualStencilFunc`，stencil pass 使用 `AlwaysStencilFunc + ReplaceStencilOp`。
- `SimulationInstanceState` 增加 `wasActive2`、`wasActive3`、`wasActive4`。完整 pass 链结束后按源码顺序推进四帧历史；当四帧均不再需要更新时，update 直接跳过 GPU pass。
- 动态 `aStencilActive` 由当前活跃态、四帧历史和可见性恢复窗口共同决定。页面从 hidden 回到 visible 时打开两帧 `forceRenderAll`，避免浏览器后台暂停后局部 tile 失去一次必要的同步。
- 普通 pass 不再清空整张 ping-pong 颜色目标，只清 stencil，再由 stencil mesh 保留活跃区域；这样不会在处理一张纸时擦掉 atlas 中其他纸片的 velocity/pigment。完整 reset 与 Full Paint 的局部 scissor reset 仍同时清颜色和 stencil。
- `qa-experience.mjs` 增加运行时结构断言：七个 target 都有 stencil、存在 stencil mesh 和 `aStencilActive`，并检查四帧活跃字段。它与既有的 ellipse、dt、Divergence、Full Paint 和 active 生命周期断言一起保留。

## 验证

- `npm exec -- tsc --noEmit`：通过。
- `node --check scripts/qa-experience.mjs`：通过。
- `npm run verify`：通过，Vite 54 modules，构建产物约 836.09 kB；`verify:integrity` 检查 73 个本地资源，`passed: true`、无 failures。仍有既有的单 bundle 大于 500 kB 警告。
- `git diff --check`：通过；输出只有现有的 LF/CRLF 转换提示。
- `npm run qa`：当前环境没有监听 `127.0.0.1:9333` 的 CDP 页面目标，返回 `ECONNREFUSED`。因此本轮尚未证明真实 GPU stencil 状态、WebGL shader 编译、多 paper tile 保留和实际 pigment 像素结果。

## 下一步

1. CDP 恢复后，在首张纸片注入 pigment，再只命中另一张纸片，读取两张纸各自的 velocity/accumulation，确认“只清 stencil、不擦其他 tile”。
2. 记录 pointer leave 后 1～5 帧的 `wasActive`、`wasActive2`、`wasActive3`、`wasActive4` 及 accumulation 衰减，确认 stencil flush 与源码生命周期一致。
3. 用 `WEBGL_lose_context`、页面 hidden/visible 和移动端固定 Full Paint 分辨率联合验证，继续推进真实运行时兼容性证据。
