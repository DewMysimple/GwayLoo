# 流体椭圆笔触 SDF 对齐

## 目标

把 Branch 的 external-force 正式路径从误用的 capsule 改回原始源码实际启用的 v2 椭圆 SDF，并保留 Branch 对纸片/地面 tile 屏幕圆度和实例隔离的适配。

## 源码证据

- `sources/original-extraction/study/app.beautified.js` 的 external-force shader 中，早期 `sdCircle`/`sdUnevenCapsule` 位于 v1 实验注释块内；实际执行的是 `sdEllipse(uv - vCenter, vec2(vScale, vScale * (1. + (planeRatio - 1.) * .5)))`。
- 原始路径随后以 `max(vLastScale, vScale)` 归一化 SDF，按 `vIsMouseDown` 分支注入 radial force 或 `mix(vForce, dir, .2)`，并在 `vWasActive == 0.` 时清空目标实例。
- 原始配置仍以 hover `mouseForce=50`、mousedown `mouseForce=.3`、`cursorSize=400/500`、`intensityVariation=.06`、pressure iterations `1` 为基线；Branch 这些契约已分别在 `PaintManager` 与 `FluidSimulation` 中承接。

## 本轮修改

- `app/src/shaders/fluid.ts`：移除 Branch 正式路径中的 `sdUnevenCapsule`，加入源码 v2 `sdEllipse`（另加等轴/极小半径保护），按 `uCurrentRadius` 的横纵半径计算屏幕圆度；恢复目标实例 `vWasActive < .5` 清零。
- `app/scripts/qa-experience.mjs`：fluid pass QA 新增 `sdEllipse`、半径 uniform、`wasActive` 清零和无 capsule 正式实现断言。
- `PaintManager.ts` 保留当前纸片投影到 simulation tile 的横纵半径换算：这是对源码 scalar `vScale + planeRatio` 的等价屏幕空间适配，不改变 `sourceScale` 的速度映射。

## 测试与验证

- 本轮将执行 TypeScript、QA 脚本语法、生产构建、资源完整性和 `git diff --check`。
- `npm run qa` 与 `npm run smoke` 仍需有效的 `127.0.0.1:9333` DevTools CDP target；没有该 target 时不能把 shader 编译、真实像素笔触或中间态截图宣称为完成。

## 结果与下一步

- 结果：Branch 源码层正式 external-force 路径已从错误 capsule 更正为 ellipse SDF，且生命周期清零语义补回。
- 遗留问题：尚无浏览器运行时 shader 编译和像素级笔触形状证据。
- 下一步：CDP 恢复后，在宽纸片、竖纸片、ground 命中、低速 hover、mousedown 和快速跨帧移动下分别采样笔触边缘、强度和 advection 尾迹；再继续核对 pressure/gradient 与纸片 LUT 的视觉输出。
