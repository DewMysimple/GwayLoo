# 烘焙相机入口与指针视差对齐

## 背景

本轮继续只修改 Branch `Dew-StanzaVerse`。对照原始提取的 `ScrollCamera` 代码与 `scene.glb` 元数据确认：`Camera_Action_Baked` 是 59.766666... 秒、只含 `Camera_Animation_Baked` translation/rotation 的长镜头；源码入口使用 5 秒 `sine.out`，桌面指针使用 NDC 乘以 `2.55°` 与 `9.2°` 的两轴力，并以 `coefRotate = 0.3` 指数接近目标。Branch 原先虽然采样 baked clip，但入口使用 cosine smoothstep，指针轴向和阻尼也不是源码数值。

## 本轮变更

- `ScrollCamera` 保留 Branch 已有的 GLB baked node/world transform 采样和 `0.1/3200` 相机裁剪面，入口改为源码 5 秒 `sine.out`；reduced-motion 直接保持最终镜头姿态。
- 指针 NDC 映射改为源码的 `rotation.x = ndc.y × 2.55°`、`rotation.y = -ndc.x × 9.2°`，追踪阻尼改为 `1 - exp(-0.3 × delta)`；用父容器语义的 world-space quaternion 同时旋转相机位置与朝向，保持 baked 镜头、纸片投影、射线和阴影使用同一个最终相机。
- 移动端和 reduced-motion 不提交鼠标视差；新增 `getDebugState()` 暴露时长、入口和指针契约，QA 按运行时值断言，并逐例核对移动端 `touchParallaxDisabled`，避免后续再把相机常数和测试各自维护。
- 继续确认射线契约没有随相机修改被替换：纸片命中保留两阶段 X 翻转，Ground 保留独立 Y 翻转；纸片/地面 simulation box 仍分别映射，树叶只接收纸片命中。

## 验证

- 用本地 `scene.glb` 只读解析确认：相机 `yfov=0.3510606418`、`znear=0.1`、`zfar=3200`；`Camera_Action_Baked` 时长 `59.7666666667`，translation/rotation 两条轨道均指向 `Camera_Animation_Baked`。
- `npm exec -- tsc --noEmit`：通过。
- `node --check scripts/qa-experience.mjs`：通过；五视口 QA 已加入 baked duration、5 秒 entry、2.55/9.2/0.3 pointer contract 和移动端禁用视差断言。
- `npm run verify`：通过，Vite 54 modules，构建产物约 836.74 kB；`verify:integrity` 检查 73 个本地资源，`passed: true`、无 failures。仍有既有的单 bundle 大于 500 kB 警告。
- `git diff --check`：通过；只有既有 LF/CRLF 转换提示。
- `npm run qa`：当前环境没有监听 `127.0.0.1:9333` 的 CDP 页面目标，返回 `ECONNREFUSED`；因此入口中间帧、鼠标视差的屏幕位移、射线命中和阴影投影仍未完成真实浏览器验收。

## 下一步

1. CDP 恢复后固定 1440×900，采样入口 0/1.25/2.5/5 秒的 camera position/quaternion 与纸片投影，确认 sine.out 和 pointer parent rotation 没有过度轨道偏移。
2. 在同一镜头位置对纸片中心、边缘、Ground 做射线命中，读取 UV、simulation box 和 pigment，确认相机 world-space 视差没有重新引入镜像。
