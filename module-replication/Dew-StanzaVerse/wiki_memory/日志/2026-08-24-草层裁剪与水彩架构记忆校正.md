# 草层裁剪与水彩架构记忆校正

## 发现

对照原始提取的 GrassLayer `_createGeometry()`，源实现会按完整 groundSize 覆盖 `InstancedBufferGeometry.computeBoundingBox()` 和 `computeBoundingSphere()`，然后保留 `frustumCulled = true`。Branch 之前只创建 0.1×0.1 的 blade 原型并开启裁剪，未提供 patch 级包围体；滚动相机移动到远处时，Three 的默认 bounds 可能在实例仍可见时错误剔除整块草。

## 修改

- `app/src/experience/world/GrassLayer.ts` 为每个 ground patch 写入与源实现一致的局部 bounding box：`x=-size.y..0`、`y=0..5`、`z=-size.x/2..size.x/2`。
- 同时写入中心 `(-size.y/2, 2.5, 0)` 和半径 `max(size.x, 2.5, size.y)` 的 bounding sphere；草层继续使用 frustum culling，而不是永久关闭裁剪。
- `app/scripts/qa-experience.mjs` 增加桌面 `grassBounds > 2.5` 断言；移动端没有完整草实例，不强制该断言。
- `app/src/shaders/ground.ts` 的注释改为真实描述：地面从 ShadowProjection 屏幕 RenderTarget 读取阴影，不再错误宣称默认纯白。
- `wiki_memory/当前状态/系统架构.md` 更正尾部状态，并记录草 patch 包围体和资源失败文字内容。

## 验证

- `npx tsc --noEmit`：通过。
- `npm run verify`：通过，生产构建和 73 项资源完整性均通过。
- `node --check scripts/qa-experience.mjs`：通过。
- `git diff --check`：通过；仅有 Git 的 LF/CRLF 提示。
- 本轮未能运行 `npm run qa`：`127.0.0.1:9333` 及常见 CDP 端口均不可用，不能用静态检查替代滚动可见性截图。

## 下一步

在可用浏览器 CDP 下优先确认草 patch 在镜头滚动经过、纸片显现前后和 Ground 命中升起/回落时的可见连续性；随后继续核对纸片法线、阴影投影和移动端资源降级的实际截图。
