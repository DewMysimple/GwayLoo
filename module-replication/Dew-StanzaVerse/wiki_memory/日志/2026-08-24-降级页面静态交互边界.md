# 降级页面静态交互边界

## 目标

提高 WebGL 不可用、初始化异常和 `prefers-reduced-motion` 下的可交付性：静态权益内容、FAQ 和 Restart 不能因为 canvas 分支没有启动而失去基本交互或可读性。

## 问题

`Advantages.init()` 原先位于 `initializeRuntime()` 内。renderer 创建失败或 reduced-motion 路径会直接跳过它，CSS 虽然展开 fallback 文本和 FAQ 答案，但 Restart 的回顶行为以及 FAQ 的语义绑定没有可靠建立。

## 本轮修改

- `app/src/main.ts`：在 renderer 创建前初始化 `Advantages`，并用独立的 `staticDomReady` 异常边界保护静态页面；WebGL runtime 不再重复初始化 DOM 控件。
- `app/scripts/qa-experience.mjs`：reduced-motion 检查现在验证 fallback 可见、5 条 FAQ 答案有实际布局高度、点击 Restart 后滚动回到顶部。

## 验证

- `npm exec -- tsc --noEmit`：通过。
- `node --check scripts/qa-experience.mjs`：通过。
- `npm run verify`：待本轮最终构建命令确认；目标仍为 53 模块构建和 73/73 资源完整性。
- 当前没有有效 DevTools CDP，因此新增加的 reduced-motion FAQ/Restart 运行时断言尚未取得真实浏览器结果。

## 下一步

CDP 恢复后，先执行 reduced-motion 390×844 的 fallback QA，再模拟 WebGL renderer 构造异常，确认两条路径都保留 FAQ 可读性、Restart 回顶和无控制台异常。
