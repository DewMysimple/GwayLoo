# Paper 交付波纹增益收窄与主工程架构边界 QA

## 背景

本轮继续在 Branch 独立工程中处理“鼠标接触 2D 图层后波纹范围过大、强度过高、像高频闪烁”的实际现象。附件截图只记录现象，不作为源码指令。先复现输入链，再区分 simulation 底层是否持续注入与 Paper 显示层是否把诊断速度场放大，避免继续误改主流体参数。

## 主工程与 Branch 的架构结论

- 根目录主工程默认入口仍是 `LegacyRuntimeBridge`，运行时加载原始压缩 `public/wp-content/themes/davidwhyte/app.js`；`?runtime=r3f` 才进入新的 R3F scaffold。
- 根目录 R3F scaffold 当前主要负责 Canvas、资产预加载、GLB/视频和基础 `MeshBasicMaterial` 呈现，尚未承担原始 Paper、Fluid、Ground、Cutouts、Grass、ShadowProjection、FullPaint 的完整 shader 输入链。因此它是主工程的兼容/推演入口，不是当前可直接替换 Branch 深层 WebGL 的事实基线。
- Branch 当前的 `paper.ts`、`fluid.ts`、`ground.ts`、`cutoutShadow.ts`、`grass.ts`、`fullpaint.ts` 与原始提取的职责对应更深；后续继续以主工程的 Definition/runtime 边界做结构解构，以 Branch 自带 `sources/original-extraction` 和真实 CDP 行为做 WebGL 事实验证，不把根目录 R3F 的浅层材质路径倒灌回 Branch。

## 复现证据与判断

- 复用唯一 Chrome CDP 9333 页面：`http://127.0.0.1:3000/?seed=47&freeze=6#autostart`，从页面左侧向首棵树移动鼠标，观察到一次移动笔划后 Paper 全局湿润混合过强；旧的 `0.04` 交付增益证据为 `app/.artifacts/qa/full-regression-2026-08-25-final/desktop-1440x900/02-large-ripple.png`。
- 在同一页面采样运行时内部状态后确认：静止悬停不会每帧继续调用 `markActive`；停止真实输入后 activity grace 会失效，普通纸片活动状态约 5 秒内清空。因此“无限扩散”的主要可见问题不是静止指针持续注入，而是 Paper 显示层将 simulation velocity 的诊断变化呈得过宽、过强。
- 将 `app/src/shaders/paper.ts` 中仅属于交付显示层的 `DELIVERY_SIMULATION_VISUAL_GAIN` 从 `0.04` 收窄到 `0.015`。不改 FluidSimulation 的 external force、advection、pressure、accumulation、源 UV 或底层 buffer，保留深层推演数据。
- 同一移动轨迹的修改后截图 `app/.artifacts/qa/ripple-gain-0015.png` 已从整树高频斜纹收敛为稳定的低幅水彩湿润响应；页面恢复后仍保持 `phase=exploring`、`assetProgress=100`、`assetsReady=true`、`error=null`、`muted=true`。

## QA

- `npx tsc --noEmit`：通过。
- `node --check scripts/qa-experience.mjs`：通过。
- `npm run verify`：73/73 素材与完整性检查通过。
- `npm run qa`：五视口、source reveal、Paper/Fluid shader gate、空闲悬停 activity、Full Paint、Poem、音频、资源失败、reduced-motion、context-loss 均通过，`passed=true`、`consoleErrors=[]`、`remoteResources=[]`；新的 QA 门禁明确要求 Paper 交付增益为 `0.015`。
- Chrome 页面恢复检查：9333 只有一个 `127.0.0.1:3000` 应用页面，服务器端口 3000 可用；没有新开重复标签页。

## 边界与后续

本轮只收窄 Paper 的最终可见响应，不宣称已完成主工程像素级一致，也不把 Branch 的深层 shader 架构替换为根目录 R3F scaffold。后续仍需在固定 seed/freeze/reveal、固定视口和固定指针轨迹下继续做主工程/Branch 中间态截图与像素差分；若继续微调，必须保持 simulation 与 delivery gain 分离。

本轮没有修改根目录主线、没有写入根目录 `wiki_memory`、没有暂存用户未跟踪的 `Start.cmd`，只做本地 Git 提交，不推送远程仓库。
