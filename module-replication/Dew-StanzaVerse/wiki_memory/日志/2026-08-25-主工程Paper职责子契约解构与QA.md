# 2026-08-25｜主工程 Paper 职责子契约解构与 QA

- 时间：2026-08-25（北京时间）
- 类型：`feature`
- 状态：`完成`
- 目标：将 Branch 中宽泛的 PaperConfig 按可观测源码职责拆成 Ground、SDF、vegetation、shadow 四个窄契约，并验证它们与 26 个纸片 manifest 对齐。
- 日志索引：[[日志/MOC_工作日志|工作日志 MOC]]

## 已确认的决策

- 根目录主工程当前可运行的 R3F 路径没有提供可直接复制的真实 Paper WebGL 底层实现，因此本轮不虚构一个主工程 `paper.ts`；以主工程源码提取的 Branch `paperManifest` 为事实来源，继续做职责解构。
- `app/src/content/paper-layers.ts` 只从只读 `paperManifest` 派生 `ground`、`sdf`、`vegetation`、`shadow` 四组契约，并通过 `ExperienceDefinition.world.paperLayers` 注入 runtime。
- `LeavesLayer` 只消费 vegetation 契约；WatercolorView 的 Ground、SDF/reveal、shadow/cutout 路径分别消费对应契约。完整 `world.papers` 暂保留给中央编排、标题和兼容层，未改动已验证的水彩材质、波纹、Reveal 或光标参数。

## 检查与操作

- 对比根目录主工程与 Branch 的 paper/world 入口，确认主工程只具备 R3F scaffold，Branch 才承载当前真实 WebGL 纸片、Ground、Cutout、树叶和阴影实现。
- 新增四类窄契约，并将职责字段从宽对象的直接消费点收窄到对应层。
- 在现有 Chrome 9333 页面上复用单一 target 运行 QA；9334、9336、9337 没有可用页面，未创建新页面。

## 文件变更

- `app/src/content/paper-layers.ts`：新增 PaperLayerContracts 及四类 source-derived 子契约。
- `app/src/experience/definition.ts`：向 world definition 注入 `paperLayers`。
- `app/src/experience/world/LeavesLayer.ts`：改用 PaperVegetationContract。
- `app/src/experience/world/WatercolorView.ts`：Ground、SDF、shadow/cutout 路径改用窄契约，中央纸片编排保留兼容 manifest。
- `app/scripts/qa-experience.mjs`：新增四类契约数量、字段和索引对齐门禁。

## 测试与验证

- `npx tsc --noEmit`：通过。
- `npm run build`：通过，73 个模块；保留既有大 chunk 警告。
- `npm run verify:integrity`：73/73 通过。
- `node --check scripts/qa-experience.mjs`：通过。
- `git diff --check`：通过；仅有 Git 对 LF/CRLF 的提示。
- Chrome QA：`report.passed: true`，`sourceRevealProfilePassed: true`，5 个场景，0 个 console errors，0 个 remote resources。
- Paper layer state：26 ground（23 启用）、26 SDF（1 fade、1 transparent）、26 vegetation（10 leaves）、26 shadow（24 cast、24 hole），四组契约均通过且与 manifest 对齐。

## 待确认长期记忆

- 视觉效果仍需在固定 seed、freeze、视口和中间 reveal 时间下与主工程做截图/像素差分；本轮只验证架构职责、运行时字段和兼容性，不以末态截图改变材质或波纹参数。
- 根目录主工程的 R3F paper scaffold 仍不能替代 Branch 已完成的 WebGL 深层实现，后续比较继续以源码提取、运行时证据和可观测行为为准。

## 问题、结果与下一步

- 结果：Branch 的 Paper 数据已从“一个宽配置被所有层共享”推进为 Definition 注入的四类窄职责契约，未破坏已有页面行为和 QA 基线。
- 遗留问题：同 seed 的主工程/Branch 中间态像素差分、波纹密度和 Ground/阴影边界仍未完成。
- 下一步：继续从主工程源码解构 Paper manifest 的剩余中央编排字段，并优先做固定中间态的视觉差分；保持单一 Chrome 页面和每轮本地 Git 提交。
