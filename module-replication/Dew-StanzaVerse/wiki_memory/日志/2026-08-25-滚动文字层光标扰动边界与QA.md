# 滚动文字层光标扰动边界与 QA

## 结论

本轮修正了 Branch 滚动文字 UI 与原始 `Q5` 组件之间的一处交互生命周期差距。Branch 原先把每次全局 `pointermove` 的 CSS 坐标直接写进 `uCursorPosition`，并把初始位置放在四边形中心；因此在尚未命中文字时，2D 文字 shader 也会持续拥有一个中心扰动源，鼠标移出文字区域后还会继续被 DOM 坐标驱动。

现在 `UIView` 按源码约束处理这条链：

- `uCursorPosition` 初始为 `(1000, 1000)`，未命中时位于画布外；
- 只有指针落入 UI 文字平面的 rect 才更新 target，移出后保留上一次源码式命中位置；
- 首次命中立即定位，后续按源码 `damping=6` 和 `1-exp(-6*delta)` 平滑追踪；
- Restart 时清除 target，避免旧的 2D 扰动位置跨生命周期残留；
- 主滚动文字恢复源码 `visibleArea=0.95` 与 `uFadeNoiseSize=0.25`，没有修改 Fluid、Paper、Reveal 或 delivery ripple gain。

## 源码依据

- 原始滚动文字创建处约 169,895 行使用 `visibleArea: 0.95`、`damping: 6`，并设置 `uFadeNoiseSize=0.25`。
- 原始 `onMousemove` 先对 UI plane 做 raycast，只有命中时更新 `_targetIntersectPosition`；`update` 中再按指数 damping lerp `uCursorPosition`。
- 原始 shader 的 `uCursorPosition` 默认值为 `(1000, 1000)`，不是画面中心。

## 边界与后续

本轮只收敛滚动文字 2D 层的 pointer target 生命周期，不把该层的输入误接入 Fluid，也不继续调整用户已确认较好的水彩波纹密度、Paper delivery gain 或叶片 PositionPass。下一轮仍优先做固定 seed/freeze/reveal、固定视口和固定指针状态下的主工程/Branch 中间态像素差分；原始 Leaves PositionPass 的异常索引公式暂不盲改。
