# ADR-007｜支线模块工作区与主线工程隔离

## 状态

`active`

## 背景

`module-replication/` 用于保存脱离 Verminoble 主程序、开发环境和资产引用的独立功能复刻项目。支线项目可能与主线拥有相同资产或相似实现，但不应改变主线工程的工作边界。

## 决策

- 未明确指定 `module-replication/<项目>/` 时，Agent 默认跳过整个支线工作区。
- 每个支线项目使用自己的 `AGENTS.md`、开发环境、资产边界和 `wiki_memory/`；是否由某个 Git 分支跟踪，不改变这些项目边界。
- 支线任务的日志、当前状态、决策和知识只写入目标项目的 `wiki_memory/`。
- 主线默认只跟踪 `module-replication/` 的入口文档并忽略项目内容；明确的测试或集成分支可以把选定项目作为根仓库普通文件纳入，但不形成 Git 子模块、嵌套仓库或运行时依赖。
- 主线 `wiki_memory/` 只记录本边界策略和主线入口规则的维护，不记录支线开发过程。

## 理由

- 防止默认上下文读取支线代码和资产，降低主线任务被错误污染的风险。
- 让支线能够独立验证、提交和回退；需要集成测试时，通过明确分支纳入普通文件，不改变主线默认隔离。
- 允许相同资产存在于不同项目，同时保持路径、依赖和运行环境的明确隔离。

## 验证方式

- 根 Agent 入口和 `module-replication/AGENTS.md` 均明确默认跳过及按项目路由规则。
- 根仓库默认只追踪两个入口文档；明确集成分支可显示选定支线项目的普通文件，且不出现子模块 gitlink。
- 两套 `wiki_memory/工具/memory_lint.py check` 分别通过，且支线日志不出现在主线日志 MOC 中。
