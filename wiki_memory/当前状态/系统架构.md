# 系统架构

## 架构概览

根目录是 Vite + React + TypeScript 单页应用。页面代码、可编辑内容、主题令牌和体验特性相互分离；当前不使用路由、后端或 CMS。

| 模块 | 职责 | 入口 |
| --- | --- | --- |
| 应用壳 | React 挂载与页面组合 | `src/main.tsx`、`src/app/` |
| 内容配置 | 原版文案、尾部、六场景、图集和源资源定义 | `src/content/` |
| 运行时状态 | 统一契约、reducer、输入、音频与性能分级 | `src/features/experience/runtime/` |
| R3F 体验 | 默认运行时、水彩 Shader、GLB 相机、资源管线与视频景观 | `src/features/experience/r3f/` |
| legacy 回退 | 旧运行时生命周期和最小 DOM 契约 | `src/features/experience/LegacyRuntimeBridge.tsx` |
| 主题样式 | 颜色、层级、响应式与无障碍降级 | `src/styles/` |
| 正式资源 | 模型、纹理、视频、音频和字体 | `public/assets/` |
| 临时兼容资源 | 压缩 WebGL、旧样式及其资源 | `public/wp-content/themes/davidwhyte/` |
| 三维二创工作区 | 运行资产副本、提取清单、Blender 镜像和重建工具 | `scene_workbench/` |

`scene_workbench/` 位于 `src/` 和 `public/` 之外，不进入 Vite 静态服务，也不是 `ExperienceDefinition` 的资源来源。正式网页继续从 `public/` 读取资产；工作区只保存本地副本和可编辑 Blender 重建。

## 体验运行时

`ExperienceRuntime` 是两个运行时共享的配置边界。默认 R3F 使用 React Three Fiber、确定性 reducer、React 启动状态和 `ExperienceDefinition`；只有 `?runtime=legacy` 才由 `LegacyRuntimeBridge` 动态加载旧 CSS 与压缩 `app.js`。React 不直接修改旧脚本。

`OriginalExperienceTail` 按只读基线源码渲染沉浸区之后的 Benefits、FAQ 与体验收尾。该区块属于连续滚动和旧运行时的 DOM 契约，但其中链接与文案只是静态参考，不提供订阅或账户服务。

R3F 从 `experienceAssets`、`sceneManifest` 和统一时间线读取全部正式资源与行为配置。资源管线向水彩 Shader 提供 atlas、mask、SDF、纸张、噪声、KTX2 和 LUT；新代码与默认网络链路均不再引用 `/wp-content/`。旧路径只为显式 legacy 回退暂存。

## 数据流

`ExperienceDefinition` 聚合控制文字、诗句、尾部、六场景和 `ExperienceAssetManifest`。R3F 只消费强类型配置；legacy 在短期回退期继续使用其内置映射。`check:architecture` 验证边界，`check:assets` 验证全部声明资源可读。

## 验证

按顺序执行：`npm run lint`、`npm run typecheck`、`npm run test`、`npm run check:architecture`、`npm run check:assets`、`npm run build`、`npm run test:e2e`。
