# 2026-08-22｜声音与 FAQ 交互回归修复

- 类型：`bug`
- 状态：已修复
- 目标：依据只读原版源码恢复右下角声音控件、可靠的背景音乐解锁，以及 FAQ 的 View/Close 展开内容。
- 日志索引：[[日志/MOC_工作日志|工作日志 MOC]]

## 事实基准

- 只读目录 `网页(1)` 的 HTML、压缩脚本和 computed style 是本轮唯一 UI 与行为依据，未修改该目录。
- 原版声音模块初始静音，在首次文档点击后加载音频并解除静音；声音控件延迟约 1.5 秒显示。
- 原版 FAQ 通过切换 `open` / `animate` 类，并在 0.8 秒内改变 `.content-wrapper` 高度来展开或关闭答案。

## 根因

- R3F 声音按钮不在原版 `.xp-section .sound` 选择器作用域，缺少右下角固定定位、尺寸和波形状态样式。
- R3F 在 React effect 中调用音频播放，可能错过浏览器的用户手势解锁窗口。
- R3F FAQ 仅切换 `open` 类，没有执行原版的内容高度动画，因此答案仍被 `height: 0; overflow: hidden` 裁掉。
- legacy 页面同时存在 React 点击处理和旧脚本点击处理，同一次点击可能被处理两次。

## 修复

- 从原版 HTML 完整恢复三段声音波形路径，并建立共享 `SourceSoundControl`。
- R3F 复刻原版右下角固定样式与 1.5 秒显示时机；首次页面点击或声音按钮点击时，在同一用户手势内加载并播放当前背景音轨。
- R3F FAQ 按原版 0.8 秒缓动执行高度展开/收起，View/Close、答案和分隔线保持原内容与布局。
- legacy FAQ 不再绑定 React 点击事件，继续只由压缩原版脚本控制，避免双重切换。

## 验证

- Vitest 覆盖 R3F FAQ 展开/关闭、legacy 所有权隔离和显式静音状态。
- Playwright 在桌面和移动端验证 legacy FAQ、R3F FAQ、三段波形、固定声音控件、真实媒体 `play()` 调用及页面尾部可见性。
- 截图检查确认 FAQ 答案不再被高度裁掉，声音波形固定在右下角。

## 遗留问题

- 浏览器仍要求至少一次用户点击才能播放有声媒体；这是浏览器自动播放策略，不是定时器故障。
- R3F 水彩材质与后处理逐帧等价仍属于既有迁移门槛，本轮未改变默认 legacy 运行时。

## 待确认长期记忆

- 无；声音与 FAQ 所有权规则属于已确认的原版兼容约束。
