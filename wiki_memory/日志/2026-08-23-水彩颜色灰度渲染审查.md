# 2026-08-23｜水彩颜色灰度渲染审查

- 时间：2026-08-23（北京时间）
- 类型：`discussion`
- 状态：`完成`
- 目标：确认原始素材颜色较鲜艳时，网页中树/水彩图层呈现灰淡效果的代码来源。
- 日志索引：[[日志/MOC_工作日志|工作日志 MOC]]

## 已确认的结论

- legacy 水彩并不是直接把原始图片贴到平面上，而是由 `BatchInkSimulation` 对应的 paint shader 重新组合颜色。
- paint shader 先把 `uPaintAtlasTexture` 的素材颜色与基于背景和法线的颜色混合，再通过 `uDryLut3d` 与 `uInkLut3d` 进行 3D LUT 调色；`uLutEnable` 默认开启。
- 水彩材质 shader 和最终后处理都调用 `getFogColorWithRatio()`，将颜色按深度、世界坐标、噪声和 fog state 混合到暖灰色雾色。
- base fog 颜色为 `vec3(0.796, 0.796, 0.761)`，opaque 状态颜色为 `vec3(0.714, 0.714, 0.714)`；`switchFogToOpaque()` 会把 `fogState.opaque` 从 0 动画到 1。
- 背景组件本身使用 `groundColor: #b4b4b4`、`skyColor: #e4e4e4`，并参与纸张颜色计算，因此素材透明区域也会显得灰白。
- 当前 R3F 预览没有复刻这套 fog/LUT/paint shader；其灰淡程度主要来自 `#e7e7e2` 背景、普通 `MeshBasicMaterial` 和渐显 opacity，不能与 legacy 的颜色链路混为一谈。

## 检查与操作

- 静态审查 legacy bundle 中水彩 paint material 的 fragment shader：背景/法线光照、paint atlas、LUT、simulation、mask、fog 和最终颜色输出。
- 静态审查全屏 fog post-process 的 `getFogColor()`、`getFogColorWithRatio()` 与 `ExperienceManager` 的 fog state 切换。
- 对照 R3F 的 `LandscapeWorld.tsx`、`R3FExperienceRuntime.tsx` 和 `VideoLandscape.tsx`。

## 问题、结果与下一步

- 结果：截图中的灰淡效果主要由 shader 调色与两层 fog 颜色混合共同造成，不是素材文件本身被重新压灰。
- 下一步：若要恢复更接近原始素材的颜色，应先做 A/B 调试，依次关闭 LUT、材质内 fog、后处理 fog，再决定保留哪些水彩质感参数。
