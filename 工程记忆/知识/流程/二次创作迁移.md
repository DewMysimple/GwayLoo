# 二次创作迁移

## 一句话结论

二次创作按照“文案数据 → 媒体映射 → 主题变量 → 交互核心”的顺序渐进迁移，先降低替换成本，再决定是否重写运行时。

## 适用范围

适用于把原始复刻逐步变成 Verminoble 个人审美品牌体验站的工作。

## 详细内容

### 第一阶段：内容抽离

- 盘点品牌名、标题、诗句、FAQ、导航和 CTA。
- 建立内容数据或配置入口，减少直接编辑 `index.html`。
- 暂时保留现有 DOM 和 class，先保证视觉与交互不变。

### 第二阶段：资源映射

- 建立场景到视频、音频、纹理和模型的明确映射。
- 继续兼容现有文件名，验证 desktop/mobile 与 base/over。
- 记录每个原创资源的来源、授权和替代状态。

### 第三阶段：主题变量

- 抽离颜色、字体、间距、动效强度和品牌视觉变量。
- 在不改核心运行时的情况下完成第一轮审美替换。

### 第四阶段：交互与架构

- 根据前面阶段暴露的边界，评估是否拆分 `app.js`。
- 只有当配置化不足以支撑复用时，才进入组件化或新构建系统迁移。

## 常见问题或陷阱

- 一开始同时改文案、资源、样式和 WebGL 逻辑，会让回归原因不可追踪。
- 只替换视觉素材却保留原品牌文案和外链，不算完成二次创作。
- 架构迁移前没有保留基线，无法比较新旧体验。
