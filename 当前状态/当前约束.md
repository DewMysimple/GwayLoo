# 当前约束

> 记录 Agent 修改项目时必须遵守的限制。没有依据的内容不要写入。

## 技术约束

- 当前基线必须继续通过 HTTP 静态服务运行。
- 现阶段不直接重写或格式化压缩后的 `app.js`；需要改变核心运行时前先建立迁移决策。
- 后续资源替换优先采用内容/资源配置化，而不是把新内容继续硬编码进 HTML 或压缩脚本。

## 兼容性约束

- 视频资源暂时保持 `desktop/mobile`、`base/over` 和场景编号 `1-6` 的目录与文件名约定。
- WebGL、KTX2/Basis 转码、Canvas、隐藏 video/audio 元素的现有加载顺序不能被无验证地改变。
- 访问页面优先使用 HTTP，不把 `file://` 作为正式验证方式。

## 质量约束

- 任何视觉或内容替换都应同时验证桌面端和移动端资源路径。
- 资源替换后要检查文件存在、媒体可读取、场景交互不被中断。
- 记忆页面必须保留事实来源和相对路径，不复制大段源代码。

## 操作边界

- 原始复刻素材在未确认授权前仅限本地实验，不视为可公开商用资源。
- 不主动删除原始资源、历史日志或基线代码。
- 公开发布前必须完成品牌替换、素材授权/替换、外链审查和缺失页面处理。
