# 系统架构

> 只记录当前有效的模块关系、数据流、运行方式和关键技术边界。

## 架构概览

当前是一个无构建步骤的静态页面快照。`index.html` 同时承载页面结构、原站文案、局部配置和第三方脚本引用；主题目录提供样式、压缩后的体验运行时和本地资源。当前没有独立后端、数据库、包管理配置或前端构建流水线。

工程分为两层：

1. **基线层**：保持原始复刻页面、WebGL 运行时、资源目录和启动方式可运行。
2. **创作层**：逐步抽离品牌文案、主题变量、场景配置和可替换媒体，服务 Verminoble 的个人审美体验站。

## 模块关系

| 模块 | 职责 | 依赖 | 入口 |
| --- | --- | --- | --- |
| 页面与内容快照 | 页面结构、品牌文字、FAQ、按钮和静态模块 | HTML、主题样式 | `index.html` |
| 主题样式 | 布局、响应式规则、加载层和页面视觉 | `style.css`、`loader.css`、字体 | HTML stylesheet 引用 |
| 体验运行时 | Canvas/WebGL、场景切换、交互、视频纹理和音频控制 | `app.js`、Mapbox、本地模型/纹理/视频/音频 | `app.js` |
| 媒体资源 | 3D 模型、纹理、LUT、MSDF、视频、音频和字体 | `resources/assets/` | 运行时按需读取 |
| 兼容资源 | WooCommerce、MemberPress、DASH、Mapbox、Stripe 等原站依赖 | 本地化 JS/CSS | HTML 脚本和样式引用 |

## 数据流或请求流

浏览器通过 HTTP 读取 `index.html`，随后加载本地 CSS、第三方兼容脚本和 `app.js`。体验运行时初始化 Canvas 与隐藏 video/audio 元素，并按场景交互选择 desktop/mobile、base/over 视频纹理及对应声音。当前页面还保留原站部分相对页面链接和外部分享链接，这些不代表本地路由或后端服务存在。

## 运行与部署

- 本地开发使用 `python -m http.server 8787`。
- 不建议直接用 `file://` 打开，因为 WebGL、KTX2/Basis 纹理和部分资源策略依赖 HTTP。
- 当前没有正式部署流程；默认仅用于本地实验。
- 公开发布前必须完成原始素材替换、版权/授权审查、外链审查和缺失页面处理。
